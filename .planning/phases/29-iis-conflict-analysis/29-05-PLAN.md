# Slice 5 — Structured reports and deterministic renderers

**Goal:** expose one canonical historical `InfeasibilityReport` with precise scope, lineage, evidence, completion, guarantee, and deterministic text/Markdown views.

**Requirements/decisions:** packet D4, §7–§8; D-012, D-014; R4.3, R9.1–R9.3, R9.6.

## Files and interfaces

- Create or extend `src/solver/report.rs`: `BackendIdentity`, `CandidateUniverseSummary`, `InfeasibilityOutcome` (`NoConflict`, `Conflict`, `NoConflictProof`), `ConflictMember`, `ConflictDeclarationSnapshot`, `CompiledRestrictionEvidence`, `NativeConflictEvidence`, `InfeasibilityStatistics`, `AnalysisWarning`, `AnalysisCompletion`, `FeasibilityProofStrength`, and `ConflictGuarantee`.
- Create `src/solver/render.rs` with `TextInfeasibilityReport<'_>` and `MarkdownInfeasibilityReport<'_>`. Both must use explicit stable field ordering and escaping. Keep `Display for InfeasibilityReport` to a concise one-line summary.
- Extend `src/solver/infeasibility.rs`/`error.rs` with typed stale-instance/revision/compilation, incomplete-mapping, unsupported-scope/provider, unknown-oracle, invalid-toggle, and recovery errors. Preserve backend identity/category/health effect.
- Wire intentional root and `advanced` exports in `src/solver/mod.rs`, `src/lib.rs`, and `src/advanced.rs`; do not expose internal reducer/session stores.
- Create `tests/iis_report.rs`, extend `tests/public_api_compile.rs`, and write the public example `docs/examples/infeasibility_analysis.md`.

## Test-first execution

- [ ] **1. Write report fixture tests.** Construct fixtures for original LP, explicit LP relaxation, portable irreducible, native-reported, incomplete partial evidence, proven-feasible `NoConflict`, and Unknown `NoConflictProof`. Assert all required lineage, instance, revision, exact `CompilationId`, backend/version, provider, scope, universe/grouping, numerical policy, completion, guarantee, members, evidence, statistics, and warning fields are present.
- [ ] **2. Write renderer golden tests.** Assert deterministic text and Markdown ordering, escaping of names/source strings, semantic names/sides/values first, and technical compiled/native evidence in a separate section. Assert `Display` is concise and does not equal either complete renderer.
- [ ] **3. Write guarantee/staleness tests.** Assert no minimum-cardinality field or string can be emitted, native evidence is not promoted, Unknown blocks irreducibility, and live report re-resolution rejects model instance/revision/`CompilationId` mismatch while historical snapshots remain readable.
- [ ] **4. Implement report/renderers.** Replace partial string membership/optional compilation identity with typed evidence and mandatory exact identity. Keep report construction independent from native provider availability.
- [ ] **5. Add docs and public API checks.** Document `OriginalLp` versus explicit `LpRelaxation`, provider modes, incomplete guarantees, no feasibility relaxation, and future function-in-set/nonlinear proof seams. Run `cargo test -p roml --test iis_report --test public_api_compile`, rustdoc with warnings denied, and package listing.

## Acceptance and stop conditions

The report is historical and self-contained; it must remain inspectable after model mutation and must not expose raw row IDs as the ordinary member identity. Stop if completion and guarantee can be conflated, if renderers depend on hash-map iteration, or if nonlinear language implies that local restoration failure is an IIS.

**Commit boundary:** `feat(iis): add structured conflict reports and renderers`.
