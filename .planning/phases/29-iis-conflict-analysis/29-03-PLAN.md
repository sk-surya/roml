# Slice 3 — Isolated LP feasibility oracle

**Goal:** run repeated zero-objective LP feasibility checks against an isolated snapshot-derived session with transactional restriction masks, exact identity validation, incremental updates, basis reuse where qualified, and recovery after uncertain rollback.

**Requirements/decisions:** packet D2, §5.2, §8, §9; D-004, D-005, D-015; R3.4–R3.6, R4.2–R4.3.

## Files and interfaces

- Extend `src/solver/infeasibility.rs` with `OracleBudget`, `FeasibilityEvidence`, `InfeasibilityEvidence`, `UnknownReason`, `FeasibilityOutcome`, `FeasibilityOracle`, `AnalysisSessionHealth`, and cache identity keyed by `CompilationId`, universe identity, numerical policy, and selection.
- Extend `src/solver/session.rs`/`backend.rs` with an isolated factory contract that receives the exact `BackendSnapshot` and `SemanticConflictUniverse`; the persistent `BackendSession` must not be reused for candidate toggles.
- Extend `src/solver/reference.rs` with a deterministic oracle that can inject apply failure, rollback uncertainty, status outcomes, rebuild count, and basis-reuse counters.
- Extend `src/compiler/restriction.rs` with transactional `apply(selection)`/`restore(receipt)` operations that validate identity before mutation.
- Add `tests/infeasibility_oracle.rs`; extend `tests/semicontinuous_recovery.rs` and `tests/end_to_end_equivalence.rs`.

## Test-first execution

- [ ] **1. Write the isolated-session test.** Solve a model through the persistent session, capture its revision/compilation/solution, run an analysis oracle from the exact `BackendSnapshot`, and assert the persistent state is byte/observation-equivalent afterward. Instrument builds and assert one analysis build before candidate checks.
- [ ] **2. Write tri-state status tests.** For each reference termination, assert `Optimal`/proven feasible maps to `ProvenFeasible`, proven infeasible maps to `ProvenInfeasible`, and `InfeasibleOrUnbounded`, `Unbounded`, limits, interruption, numerical, backend errors, and unknown map to `Unknown`. No status test may accept an infeasible result for an ambiguous or limited termination.
- [ ] **3. Write transactional toggle tests.** Apply a selection, check it, restore it, and compare the backend state with the original exact snapshot. Assert row-side/bound-side indices remain stable, all bound-stack layers restore, and a cache hit is rejected across a different compilation, universe, numerical policy, or selection.
- [ ] **4. Write failure-recovery tests.** Inject a failed apply and an uncertain rollback. Require the analysis session to become `RequiresRebuild`, require a snapshot rebuild before another check, and assert the persistent session remains healthy. Extend the semi-continuous partial-apply regression to prove no replayable model operation is lost.
- [ ] **5. Implement status triage and recovery.** Use one zero-objective solve per check, convert only certified statuses to proven outcomes, return `Unknown` for all uncertain paths, and invalidate cached outcomes after recovery. Native failure may fall back in `Auto` only after isolation/rebuild is proven safe.
- [ ] **6. Verify differential behavior.** Compare incremental mask checks with a fresh full snapshot projection for every generated bounded selection sequence. Run focused tests, core checks, and record build/rebuild/mask/cache counters in `P29_ORACLE.md`.

## Acceptance and stop conditions

The slice passes only when candidate toggles are transactional, exact identity is checked before every transition, uncertain rollback requires rebuild, and no per-candidate rebuild occurs in the normal path. Stop if the backend cannot preserve stable indices or cannot distinguish proven infeasible from Unknown under its official status contract.

**Commit boundary:** `feat(iis): add isolated tri-state LP feasibility oracle`.
