# Slice 6 — Native HiGHS IIS provider

**Goal:** add a separately labeled, version-qualified native HiGHS IIS provider in `roml-highs/src/iis.rs`, using native output as a semantic-reduction seed for `Auto` and returning typed `Unsupported` everywhere qualification is absent.

**Requirements/decisions:** packet §6 and D1/D3; D-006, D-009, D-010, D-014; R5.1, R5.2, R5.9–R5.11, R6.1, R7.4.

## Mandatory audit before production references

- Inspect the exact generated `highs-sys` 1.15.0 Rust symbols and the matching official HiGHS 1.15.0 C header/source. Record signatures, ownership, argument lengths, return codes, status semantics, IIS strategy constants, lifecycle, model-class restrictions, and row/column/lower-bound/upper-bound membership states in `docs/knowledge/highs_iis_api.md`.
- Inspect every supported system version separately, including the configured system-discovery/build mode and whether the IIS symbols are present in its header and library. Record the actual version and compile/link/run result, not only a runtime version string.
- Use `cargo metadata --format-version 1` to locate the resolved `highs-sys` source and `rg` against the inspected official/generated files. Do not infer a symbol from docs, another version, a handwritten wrapper, or a numeric value.
- Determine the compile gate before adding `roml-highs/src/iis.rs` references. A missing IIS symbol must make that provider unavailable at compile time for that feature/version; a runtime check alone is insufficient.
- Audit `roml-highs/src/ffi.rs` and `bindings.rs`. IIS code must use only `highs-sys` generated bindings. If a needed official symbol is absent, stop and document the upstream/fork decision; do not add an `extern "C"` declaration.

## Files and interfaces

- Create `roml-highs/src/iis.rs`: an adapter-local `HighsNativeIisProvider` implementing the core `InfeasibilityOracleFactory`/native-conflict request contract. Return row membership, column membership, lower-bound membership, upper-bound membership, possible/member/excluded state, exact backend version, and exact `CompilationId`.
- Modify `roml-highs/src/session.rs`: advertise native IIS only for the audited symbol/version/model-class matrix. Do not mark `BackendFeature::Iis` as native merely because portable ROML IIS exists. Expose portable capability separately.
- Modify `roml-highs/src/compiler.rs`: provide only audited compiled-index maps and exact snapshot identity needed by `iis.rs`; reject a mismatched `CompilationId` before native mapping.
- Modify `roml-highs/src/bindings.rs` only for re-export/use of generated symbols. Modify `roml-highs/src/ffi.rs` only to remove/migrate conflicting handwritten IIS declarations if the audit proves they are present; never add declarations there.
- Modify `roml-highs/src/lib.rs` for feature-gated module wiring. Create `roml-highs/tests/iis.rs`, extend `conformance.rs`, and create both audit/qualification evidence files.

## Test-first execution

- [ ] **1. Commit the audit as a failing characterization.** Add tests that compile the provider only when the audited generated IIS symbols are available and report typed `Unsupported` otherwise. Record the expected failure against the current partial binding surface before implementation.
- [ ] **2. Add capability/version tests.** Test bundled 1.15.0, each supported system version, an old/unqualified version, missing symbols, unsupported model class, and unavailable native library. Assert `NativeOnly` rejects/fails typed and `Auto` can use portable ROML without pretending native support.
- [ ] **3. Add extraction tests.** Against an official/qualified fixture, preserve row, column, lower-bound, upper-bound, possible/member/excluded native states and exact `CompilationId`. Assert every native return code is checked and mapped to typed backend errors.
- [ ] **4. Add semantic-seed tests.** Feed native compiled members through the restriction-level map, reject stale identity, group generated restrictions, re-reduce semantically, and run the fresh final verifier. Assert provider chain says `HiGHS native seed → ROML semantic reducer → verifier` for `Auto`.
- [ ] **5. Implement only audited calls.** Keep native data as optional evidence; never use native minimality to set ROML `Irreducible`. Native failure in `Auto` may fall back only after the isolated session is unchanged or rebuilt; `NativeThenRoml` requires the native seed; `NativeOnly` returns the native report/typed unsupported outcome without fallback.
- [ ] **6. Run the qualified matrix.** Run bundled and each system-version command from `29-PLAN.md`; record compiler/linker/runtime/library versions, symbols, model class, return codes, and skipped cells in `P29_HIGHS_IIS_QUALIFICATION.md`.

## Acceptance and stop conditions

Stop native work if any signature/layout/status/strategy value is inferred rather than read from an authoritative versioned source, if a system version cannot be compile-gated, if the native session can partially mutate the persistent session, or if semantic re-reduction cannot be performed. In all such cases preserve and document portable ROML IIS and return typed `Unsupported` for native requests.

**Commit boundary:** `feat(highs): add audited native IIS provider` only after the header/version audit and bundled/system tests are attached.
