# Slice 7 — Qualification, differential, mutation, and performance evidence

**Goal:** qualify the complete P29 LP feature with reproducible correctness, recovery, native/portable, version, and planted-IIS performance evidence, then stop before MIP/nonlinear scope.

**Requirements/decisions:** packet §10–§14; D-014, D-015, D-017; R3.5, R7.4, R8.1–R8.3, R9.4, R9.6.

## Evidence files and test corpus

- Create `tests/iis_qualification.rs` for deterministic core correctness and public contract cases.
- Create `tests/iis_differential.rs` for portable versus native-seeded results; valid differing IIS sets are accepted, but every returned set is independently verified.
- Extend `tests/iis_mutation.rs` with malformed origins/toggles, stale identities, rollback failure, bound-stack corruption, Unknown promotion, and verifier bypass mutations.
- Create `tests/iis_planted.rs` and `benches/iis.rs` for deterministic planted conflicts with increasing irrelevant-constraint counts and conflict sizes. Follow existing benchmark conventions; if no benchmark harness is present, use a reproducible test binary and record machine metadata.
- Extend `roml-highs/tests/iis.rs` for bundled and system qualification; update `docs/examples/infeasibility_analysis.md` with plan-driven usage, mode selection, explicit LP-relaxation labeling, partial guarantees, and unsupported diagnostics.
- Create `docs/release/evidence/P29_IIS_QUALIFICATION.md` and complete `P29_HIGHS_IIS_QUALIFICATION.md` with commands, versions, outputs, skipped checks, residual risks, and independent review findings.

## Test-first execution

- [ ] **1. Add the correctness corpus.** Cover contradictory variable bounds; two-row/multi-row IISs; redundant constraints; equality and ranged-row sides; lower/upper bound membership; persistent fixing/lock/temporary fixing provenance; a grouped construct; two distinct IISs; stale `CompilationId`; feasible model; Unknown initial check; time/call/iteration-limited partial runs.
- [ ] **2. Add independent verification helpers.** For every complete portable result, independently solve the selected atom set as infeasible and every single-atom deletion as feasible under the recorded oracle/numerical policy. Fail the test if the report says `Irreducible` without these results.
- [ ] **3. Add differential cases.** Compare native HiGHS evidence, native-seeded ROML reduction, portable full-universe reduction, and reference projection. Do not compare member sets for equality when multiple valid IISs exist; compare semantic validity, guarantee discipline, scope, provider chain, and exact identity.
- [ ] **4. Add mutation gates.** Run mutations for missing origin entries, malformed toggle plans, stale identity acceptance, rollback failure ignored, Unknown mapped to infeasible, incomplete report promoted to irreducible, native row set promoted without semantic re-reduction, and bound layer restored to infinity. Each mutation must fail a focused test.
- [ ] **5. Add version qualification.** Execute bundled HiGHS 1.15.0 and every supported system version through compile, link, load, and LP-IIS run gates. Record unqualified/absent-library behavior as typed `Unsupported` with diagnostics. Do not mark unavailable cells as passing.
- [ ] **6. Add performance evidence.** Compare naive full-universe one-at-a-time deletion, native-only result, native-seeded ROML reduction, and portable adaptive deletion. Record wall time, oracle calls, cumulative LP iterations, factorizations if available, rebuild count, basis reuse, cache hits, peak memory, seed size, and final size. Accept the hybrid only when final semantic verification/guarantee is unchanged, it is not pathologically worse than naive on the corpus, and it materially improves at least large sparse planted cases.
- [ ] **7. Run the complete matrix and reviews.** Run the commands in `29-PLAN.md`, inspect every `cargo package --list` for publishable crates touched by the phase, update evidence, request independent specification/correctness and integration/operations reviews, and resolve all P0/P1 findings. Do not update `.planning/STATE.md` to “complete” without verified evidence and review results.

## Acceptance and stop conditions

Phase 29 stops with qualified LP behavior only. It must not add a MIP conflict algorithm, integrality-only claims, nonlinear IIS terminology, feasibility relaxation, all-IIS enumeration, or minimum-cardinality optimization. If performance improvements require weaker recovery or guarantee semantics, reject the optimization. If a native version is unqualified, keep that cell explicitly unsupported while portable ROML remains available.

**Commit boundary:** `test(iis): qualify LP conflict analysis` followed by the independent review/evidence gate. No release/tag/publication action is authorized by this plan.
